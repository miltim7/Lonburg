Проверка улучшений взаимодействия — 6 сентября 2026

Сохранены структура, тексты, фотографии, цвета, типографика и композиция лендинга.

Что изменено:

- Однократное появление крупных блоков через IntersectionObserver: opacity и translateY, 600 мс, смещение 16 px, stagger до 165 мс. На мобильных — 450 мс, 8 px, без stagger. Первый экран не скрывается при гидратации; фокус клавиатуры сразу показывает нужный блок.
- Параллакс только у hero: до 16 px. Один пассивный обработчик планирует requestAnimationFrame только при прокрутке видимого hero. Нет постоянного цикла, чтения размеров на каждом кадре или новой библиотеки анимаций. На сенсорных устройствах и мобильных экранах параллакс отключён.
- Три панели автомобилей занимают одну ячейку CSS Grid, поэтому высота учитывает весь контент и не прыгает. Crossfade и движение текста занимают 350 мс. Существующий синий индикатор перемещается через transform. Переключение ждёт загрузки фото; поздний ответ не отменяет последний выбор. Неактивные панели исключены из навигации и дерева доступности через inert и aria-hidden.
- FAQ использует button, aria-expanded, aria-controls и связанные области ответа. Grid 0fr → 1fr, opacity, движение текста и поворот chevron работают в обе стороны за 320 мс; на мобильных — 260 мс.
- Якоря учитывают высоту фиксированной шапки через scroll-margin-top. Prefers-reduced-motion отключает анимации, параллакс и smooth scroll, в том числе при изменении настройки во время просмотра.

Изображения:

- Все шесть существующих WebP имеют размер 1536×1024 и весят 80–161 КиБ. Чрезмерно больших исходников нет; повторное сжатие исходников не выполнялось.
- Используется next/image, fill в контейнерах с заданной геометрией, object-fit и sizes по реальной сетке. AVIF/WebP выдаются оптимизатором. Hero использует quality=80, остальные — 75.
- Только hero имеет preload. Это актуальная замена устаревшего priority в установленном Next.js 16.3.4. Остальные пять изображений имеют loading=lazy; фотографии категорий загружаются вблизи секции для готового crossfade.
- Шесть blur-placeholder занимают суммарно 366 байт бинарных миниатюр, около 640 байт в виде data URL. Генератор: scripts/image-audit.mjs.
- При эмуляции 390 px / DPR 2 браузер выбрал 750 px для категорий и интерьера, 828 px для финального фона, 1200 px для hero с существующим широким кадрированием. Файлы 2000 px на этом экране не запрашивались. Все ответы изображений — HTTP 200, AVIF.

Результаты:

- npm run lint, npm run typecheck, npm run build — успешно.
- 12 Playwright-тестов — успешно. Проверены ширины 360, 375, 390, 430, 768, 1024, 1280, 1440, 1600 px, ошибки консоли, загрузка фотографий, меню, форма, FAQ, быстрые клики, отложенная загрузка, клавиатура, фокус, якоря и динамический reduced motion.
- Axe: нет нарушений WCAG A/AA в проверенных состояниях desktop, мобильного меню, открытого FAQ и невалидной формы. Контраст проверяется в завершённых состояниях; анимации проверяются отдельными тестами.
- Локальный Chrome, production-сборка: медиана кадра 16,7 мс, p95 17 мс, около 60 FPS на обоих профилях. Во время диагностической прокрутки не было кадров дольше 50 мс или long tasks. CLS: desktop 0,000192; мобильная эмуляция 0. Ошибок консоли нет.
- Проверены скриншоты всех секций, hero и footer на desktop и mobile. Для скриншотов секций анимации завершены и фиксированная шапка скрыта только средствами screenshot API, чтобы она не перекрывала длинные снимки. Hero снят с обычной шапкой.
