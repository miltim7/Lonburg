# Лонбург

Готовый первый вариант лендинга о подборе и доставке автомобилей из Китая в Россию. Next.js App Router, React, TypeScript, Tailwind CSS. CMS и отдельный backend не установлены. Форма заявки отправляет данные на настраиваемый endpoint.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Для production:

```bash
npm run build
npm start
```

Для тестовой выгрузки на обычный FTP-хостинг REG.RU:

```bash
npm run build:reg-hosting
```

Команда создаёт статическую папку `out` и переключает форму на `/send.php`. На REG.RU нужно выгружать содержимое `out` в папку сайта на FTP-хостинге. Обработчик `send.php` отправляет заявки на `bovart.1979@gmail.com`; Telegram можно включить на PHP-хостинге через переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, если хостинг позволяет задавать переменные окружения.

Next.js требует Node.js 20.9+. Для совместимости со всей цепочкой инструментов разработки используйте Node.js 22.13+ или 24. В текущем окружении Node.js 20.14 проверки также прошли, но npm сообщает о несовпадении engine у вложенной зависимости ESLint. [Документация установки Next.js](https://nextjs.org/docs/app/getting-started/installation).

## Дизайн

- Графитовый первый экран, светлые тёплые секции, умеренный синий акцент.
- Локальный Manrope с кириллицей; браузер не обращается к Google Fonts.
- Временный типографический знак «ЛОНБУРГ», шесть сгенерированных автомобильных изображений без марок и четыре клиентские фотографии крупной строительной техники.
- Категории с переключением, линия этапов, визуальная смета, схема двух договоров, маршрут Китай → Россия → город клиента.
- Отдельные мобильные композиции, клавиатурное управление, системная настройка reduced motion.
- Без выдуманных цен, отзывов, кейсов, сотрудников или обещаний гарантированного срока. Телефон и почта взяты из присланного клиентом договора.
- Есть отдельный блок профессионального подбора автомобилей по России.
- Крупная строительная техника и высокотехнологичное оборудование представлены двумя равными карточками с переходом к контактам; фотографии техники вынесены в отдельную галерею под карточками и открываются крупнее по клику. Каталога, кейсов и неподтверждённого процента экономии нет.
- В блоке стоимости есть пояснение о факторах утильсбора; тарифная таблица и формула 0,45 не опубликованы. Учтено отдельное вознаграждение за сопровождение из договора.

## Где редактировать

| Данные                                                                                       | Файл                     |
| -------------------------------------------------------------------------------------------- | ------------------------ |
| Название, телефон, email, Telegram, MAX, юридическое название                                | `src/config/company.ts`  |
| Заголовки, описания, этапы, стоимость, сроки, договоры, преимущества, поля и сообщения формы | `src/data/landing.ts`    |
| Вопросы и ответы                                                                             | `src/data/faq.ts`        |
| Навигация, основной CTA, интерфейсные подписи                                                | `src/data/navigation.ts` |
| Пути изображений, alt, позиционирование                                                      | `src/data/images.ts`     |
| Title, description, Open Graph, домен                                                        | `src/config/seo.ts`      |
| Цвета, размеры, отступы и адаптив                                                            | `src/app/globals.css`    |

Телефон и email заполнены в `src/config/company.ts` по договору клиента. Компонент `src/components/ui/contact-options.tsx` показывает действующие ссылки под формой и в подвале. Telegram и MAX скрыты до получения настоящих адресов. Если все контакты пустые, компонент показывает явно подписанные некликабельные заглушки. В Telegram/MAX указывайте полный настоящий URL; телефон — номер, email — адрес. Не записывайте демонстрационные значения в конфигурацию действующих контактов.

Изображения для сайта: `public/images/automotive-hero.webp`, `public/images/automotive-suv.webp`, `public/images/machinery-1.webp` — `public/images/machinery-4.webp`, превью ссылки — `public/images/og.jpg`. Оригиналы и точные промпты сгенерированных автомобильных изображений: `output/imagegen/`. Клиентские фотографии техники используются только в разделе “Крупная строительная техника” и не оформлены как кейсы или выполненные поставки.

## Форма и будущий калькулятор

Изолированный компонент `src/components/sections/estimate.tsx` принимает `EstimateContent` и серверный блок контактов через props. Поля: модель, состояние, год выпуска, мощность, объём двигателя, город, телефон/Telegram, имя, выбор по таможне/утильсбору и комментарий.

Форма проверяет обязательные поля, допустимую длину, телефон и Telegram. Отправка идёт `application/x-www-form-urlencoded` POST на адрес из `NEXT_PUBLIC_ESTIMATE_FORM_ENDPOINT`. Для Netlify используется `/__forms.html`: статический скелет формы лежит в `public/__forms.html`, а `form-name=lonburg-request` позволяет Netlify принять заявку.

Netlify в этой схеме — только временный технический приёмник для тестового домена. При финальном хостинге замените `NEXT_PUBLIC_ESTIMATE_FORM_ENDPOINT` на реальный endpoint: API сайта, CRM, Make/Zapier/webhook, Telegram-бот или другой согласованный канал. Если временно остаётесь на Netlify, проверьте: Forms → `lonburg-request` → Form notifications → Add notification → Email notification.

Для уведомлений в Telegram есть функция `netlify/functions/form-to-telegram.js`. В Netlify нужно добавить переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, затем создать Forms webhook на адрес `https://lonburg-auto.ru/.netlify/functions/form-to-telegram` для формы `lonburg-request`.

Точка подключения будущей CRM/бота — `submitEstimate()` в `src/lib/estimate.ts`. При интеграции замените Netlify-адаптер, расширьте тип результата, добавьте серверную валидацию, обработку ошибок, защиту от повторных запросов и согласованные документы обработки данных. Подтверждение показывается только после успешного ответа на POST. Сообщения формы редактируются в `src/data/landing.ts`.

Никаких формул расчёта и фиктивных тарифов нет. Сейчас блок работает как расширенная заявка, которая собирает параметры для ручного расчёта. Будущий калькулятор можно поставить на место `Estimate`, сохранив якорь `#estimate`; реальные тарифы и коэффициенты должны поступать из согласованного источника.

## Подготовка к Payload CMS

`src/types/content.ts` описывает контракты `LandingPageContent`, `HeroContent`, `ProcessStep`, `FAQItem`, `EstimateContent`, `CompanyConfig`, `SEOConfig` и медиа.

`src/lib/content.ts → getLandingPage()` — серверная граница источника контента. Сейчас она возвращает локальный объект. При подключении Payload замените её запросом к CMS и преобразованием результата в `LandingPageContent`. Секции получают данные через props и не знают о способе хранения. Изображения имеют единый интерфейс `Media`, повторяющиеся сущности представлены массивами, структура страницы остаётся в серверном `src/app/page.tsx`.

Контакты, навигацию и SEO можно получать из globals CMS на уровне страницы/layout. Для удалённых изображений добавьте конкретные доверенные `remotePatterns` в Next config. CMS, базу данных и админку сейчас устанавливать не нужно.

## Что получить от клиента перед публикацией

1. Настоящие контакты: Telegram, телефон, email; MAX — только после создания.
2. Реальный домен и юридические реквизиты.
3. Утверждённые тексты документов и обработки персональных данных для заявок.
4. Согласовать финальный канал заявок: email, Telegram, MAX, CRM, webhook или backend сайта.
5. Утверждённый логотип, фирменная палитра и изображения с правами на публикацию, если временное оформление заменяется.
6. Примеры договоров и подтверждение актуальных условий работы, сроков и экспортных ограничений.

После назначения домена скопируйте `.env.example` в `.env.local`, задайте `NEXT_PUBLIC_SITE_URL` и пересоберите. Без домена сайт намеренно имеет `noindex`, robots запрещает индексацию, sitemap пуст: выдуманные URL не публикуются. После настройки автоматически появятся canonical, адреса Open Graph и sitemap. Проверка актуальных правил экспорта для реальных сделок остаётся задачей компании; сайт использует информацию из задания.

## Проверки

```bash
npm run lint
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Если на Windows используется установленный Edge:

```powershell
$env:PLAYWRIGHT_CHANNEL='msedge'
npm run test:e2e
```

Playwright запускает production-сервер автоматически либо использует работающий localhost:3000. Проверяются 1600, 1440, 1280, 1024, 768, 430, 390, 375 и 360 px; отсутствие overflow и сломанных изображений; консоль; меню и возврат фокуса; якоря; категории и FAQ с клавиатуры; валидация и POST формы Netlify; axe WCAG A/AA; reduced motion и SEO-маршруты.

Скриншоты всех ширин сохраняются в `test-results/`. Отдельный визуальный проход: `node scripts/visual-qa.mjs`, результаты — `output/screenshots/`. Автоматические проверки доступности дополняют ручной осмотр и не являются сертификатом соответствия.
